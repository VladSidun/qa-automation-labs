# Лабораторна робота 2

Модульне тестування бізнес-логіки засобами Vitest. Варіант 12.

Виконавець: впишіть власне прізвище та ім’я. Група: впишіть свою групу.

Ця папка — продовження лабораторної 1 з доданим модулем замовлення.
Першу папку залишено окремо, щоб можна було перевірити кожну роботу.

## Суть роботи

Перевірити всі функції готового модуля замовлення: вартість позицій, знижку,
доставку та підсумкову суму. Додати розрахунок розстрочки за варіантом 12.
Застосувати параметризовані тести, перевірити межі й винятки,
виміряти покриття та виконати експеримент із тестом без твердження.

## Специфікація розстрочки

Умова задає 3, 6 та 12 місяців і 2 % за кожні три місяці.
Прийняте трактування: надбавка до всієї початкової суми становить
2 %, 4 % і 8 % відповідно. Відсотки не капіталізуються.

Місячний платіж: `total * (1 + months / 3 * 0.02) / months`,
з округленням до копійок.

| Початкова сума | Місяці | Надбавка | Місячний платіж |
| -------------- | ------ | -------- | --------------- |
| 12000          | 3      | 2 %      | 4080            |
| 12000          | 6      | 4 %      | 2080            |
| 12000          | 12     | 8 %      | 1080            |
| 1000           | 6      | 4 %      | 173.33          |

Інші строки, включно з дробовими, відхиляються з `INVALID_MONTHS`.
Від’ємна сума, `NaN` та нескінченність — `INVALID_TOTAL`.
Нульова сума дозволена. Округлення та перевірка суми — явно прийняті
уточнення до короткої умови варіанта.

Повертається один округлений місячний платіж. Наприклад, 173.33 × 6 = 1039.98,
тому ця функція не складає графік із коригуванням останнього платежу.

## Чому саме такі перевірки

`it.each` запускає однакову перевірку для кількох наборів даних.
В очікуваних результатах записані готові числа, а не копія формули.
Грошові та дробові результати порівнюються через `toBeCloseTo`.
Для помилки в `expect` передається функція: `() => calcInstallment(...)`.

Строки перевіряються як дискретний набір: 4 і 5 місяців не дозволені,
хоча вони лежать між 3 і 6. Для кожного дозволеного строку є
значення на один менше та на один більше.

## Експеримент із покриттям

1. Запустіть `npm run coverage`, збережіть показники.
2. Тимчасово додайте в `tests/order.test.ts`:

```typescript
it('виклик без перевірки результату', () => {
  calcOrderTotal([item(100)], 'silver');
});
```

3. Повторіть вимірювання та порівняйте показники.
4. Видаліть цей тест і знову запустіть набір.

Якщо попередній набір уже має 100 %, показники не зміняться.
Тест без твердження може виконувати код і збільшувати покриття,
але не перевіряє правильність поверненого результату.

## Для здачі

Потрібні титульний аркуш, мета і варіант, таблиця вхідних умов,
лістинги тестів з поясненням, власні скриншоти прогону й покриття,
результат експерименту, специфікація й код розстрочки, висновки,
посилання на репозиторій та запит на злиття.

Рецензію пишуть на реальний код однокурсника: щонайменше три змістовні
зауваження про межі, очікувані значення, матчери, назви або незалежність тестів.
Рецензію потрібно додати після перегляду роботи однокурсника.
