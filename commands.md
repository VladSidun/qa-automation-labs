# Команди для демонстрації лабораторних робіт

## 1. Перевірка інструментів

```powershell
# Відкрийте PowerShell у корені репозиторію та збережіть його шлях.
$labsRoot = (Get-Location).Path

# Показуємо версії інструментів для звіту.
node -v
npm -v
git --version
```

Проєкти перевірено з Node.js 24.14.0, npm 11.9.0 і Git 2.47.1.windows.2.
Для встановлених версій залежностей використовуйте Node.js 24.

## 2. Лабораторна 1 — середнє арифметичне

```powershell
# Переходимо до першого проєкту.
Set-Location -LiteralPath (Join-Path $labsRoot 'qa-automation-lab-1')

# Показуємо основні папки й конфігурації, включно з прихованими файлами.
Get-ChildItem -Force

# Перевіряємо, що всі залежності встановлені.
npm ls --depth=0

# Показуємо реалізацію свого варіанта та його тести.
Get-Content -LiteralPath '.\src\average.ts' -Encoding utf8
Get-Content -LiteralPath '.\tests\average.test.ts' -Encoding utf8

# Запускаємо тільки тести середнього арифметичного: очікується 9 успішних.
npm test -- tests/average.test.ts

# Запускаємо всі тести першої роботи: очікується 15 успішних.
npm test

# Запускаємо тести з вимірюванням покриття: очікується 100 %.
npm run coverage

# Відкриваємо HTML-звіт покриття в браузері.
Invoke-Item -LiteralPath '.\coverage\index.html'

# Перевіряємо код лінтером, типи TypeScript і форматування.
npm run lint
npm run typecheck
npm run format:check
```

Для пояснення на захисті: `[4, 8, 12]` дає `8`; масив з одним елементом
повертає цей елемент; порожній масив спричиняє `EMPTY_ARRAY`.
Тест із `toThrow` вважається успішним, якщо очікувана помилка виникла.

## 3. Лабораторна 2 — замовлення та розстрочка

```powershell
# Переходимо до другого проєкту.
Set-Location -LiteralPath (Join-Path $labsRoot 'qa-automation-lab-2')

# Показуємо встановлені залежності та додані файли.
npm ls --depth=0
Get-ChildItem -LiteralPath '.\src', '.\tests'

# Показуємо модуль замовлення: calcInstallment розміщена наприкінці файлу.
Get-Content -LiteralPath '.\src\order.ts' -Encoding utf8

# Показуємо тести свого варіанта.
Get-Content -LiteralPath '.\tests\installment.test.ts' -Encoding utf8

# Перевіряємо тільки розстрочку: очікується 28 успішних тестів.
npm test -- tests/installment.test.ts

# Перевіряємо показовий модуль замовлення: очікується 33 успішних тести.
npm test -- tests/order.test.ts

# Запускаємо весь проєкт, включно з тестами першої роботи: 76 успішних.
npm test

# Перевіряємо покриття всього проєкту: очікується 100 %.
npm run coverage

# Відкриваємо звіт; для деталей натискаємо на order.ts.
Invoke-Item -LiteralPath '.\coverage\index.html'

# Перевіряємо лінтер, типи та форматування.
npm run lint
npm run typecheck
npm run format:check
```

Для пояснення на захисті: для 12000 грн платіж на 3 місяці — 4080 грн,
на 6 — 2080 грн, на 12 — 1080 грн. Надбавка становить відповідно 2 %, 4 %
та 8 % від початкової суми. Дозволені лише ці три строки.
Значення `2/3/4`, `5/6/7`, `11/12/13` перевіряють дозволені строки й сусідні значення.
Платіж округлюється до копійок; графік із коригуванням останнього платежу
ця функція не формує.

## 4. Демонстрація автоматичного перезапуску

```powershell
# Переходимо до першої роботи й запускаємо спостереження за тестами.
# Явний --watch примусово вмикає цей режим і в середовищі CI.
Set-Location -LiteralPath (Join-Path $labsRoot 'qa-automation-lab-1')
npm run test:watch -- --watch tests/average.test.ts
```

Поки ця команда працює, відкрийте `tests/average.test.ts` у редакторі.
У першому тесті змініть `expect(result).toBe(8)` на `expect(result).toBe(9)`
та збережіть файл. Vitest автоматично покаже помилку: отримано 8, очікувалося 9.
Поверніть 8, збережіть файл і покажіть успішний повторний прогін.
Завершіть режим спостереження клавішею `q` або `Ctrl+C`.

## 5. Експеримент із тестом без твердження

```powershell
# Спочатку фіксуємо звичайний результат: 76 тестів, покриття 100 %.
Set-Location -LiteralPath (Join-Path $labsRoot 'qa-automation-lab-2')
npm run coverage
```

Тимчасово додайте наприкінці `tests/order.test.ts` такий код:

```typescript
it("виклик без перевірки результату", () => {
  calcOrderTotal([item(100)], "silver");
});
```

```powershell
# Після додавання запускаємо знову: 77 тестів, покриття залишиться 100 %.
npm run coverage
```

Потім видаліть саме доданий тест і збережіть файл.

```powershell
# Підтверджуємо повернення до початкового набору: 76 тестів.
npm run coverage
```

Висновок: виклик без твердження виконує код, але не перевіряє правильність
результату. У цьому проєкті покриття вже повне, тому додатковий тест його
не змінює. У звіті достатньо записати показники до й після експерименту.
У фінальному наборі тимчасового тесту немає.

## 6. Якщо залежності потрібно відновити

Виконуйте в папці потрібної лабораторної після перенесення проєкту
на інший комп’ютер або за відсутності `node_modules`:

```powershell
# Перевстановлює залежності за точними версіями з package-lock.json.
# Для завантаження пакетів може знадобитися інтернет.
npm ci
```

Після встановлення виконайте `npm test`. Команда `npm ci` замінює
наявний `node_modules`, тому повторювати її перед кожною демонстрацією не потрібно.

## 7. Найкоротший сценарій показу

У папці кожної лабораторної виконайте:

```powershell
# Тести, покриття, звіт у браузері, перевірка коду й типів.
npm test
npm run coverage
Invoke-Item -LiteralPath '.\coverage\index.html'
npm run lint
npm run typecheck
```

Покажіть реалізацію свого варіанта, позитивний тест, межове значення й тест
на виняток. Для другої роботи додатково поясніть `it.each` і `toBeCloseTo`.
