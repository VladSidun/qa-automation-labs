# Лабораторна 5 — конспект 20/80

## Для чого робота

API-тест перевіряє систему через HTTP, як її викликає клієнт. Він охоплює маршрут, перевірку доступу, валідацію, розрахунок і збереження. Окремий модульний тест формули цього не доводить.

## Запит і відповідь

Запит містить метод (POST/GET/DELETE), адресу, заголовки та, за потреби, JSON-тіло. Відповідь має код стану, заголовки й тіло. У цій роботі 200 — успішне читання або вхід, 201 — створення, 204 — видалення без тіла, 400 — валідація, 401 — немає прийнятної автентифікації, 404 — відсутній або чужий ресурс.

## П’ять рівнів

1. Код: POST повернув 201.
2. Структура: Ajv підтвердив JSON Schema відповіді.
3. Значення: для basic сума 500 + доставка 60 = 560; sku збережено точно.
4. Заголовки: Content-Type містить application/json, Location веде до /orders/<отриманий id>.
5. Побічний ефект: наступний GET повертає створений ресурс. Після хибного SKU список залишається порожнім.

## Ізоляція

createApp створює нові Map токенів і замовлень. beforeEach створює новий застосунок, входить користувачем і отримує токен. Тест не залежить від попереднього запуску. Supertest приймає app і тимчасово використовує локальний порт; окремий npm start для цих тестів не потрібен. Для Postman/Newman сервер запускається окремо.

## Автентифікація й авторизація

Токен доводить вхід конкретного користувача. Bearer — схема заголовка Authorization, а не частина самого токена. Валідний токен без Bearer відхиляється. Чужий id повертає 404: відповідь не підказує сторонній особі, чи існує замовлення. Тест перевіряє не тільки помилку, а й те, що власник усе ще може прочитати ресурс після чужої спроби видалення.

## JSON Schema

required означає обов’язкові поля; type визначає тип, enum — набір значень, format — форму UUID або дати (через ajv-formats), minimum — нижню межу. additionalProperties: false забороняє зайві поля. allErrors: true показує всі знайдені порушення. Схема не замінює арифметичну перевірку: і 560, і помилкові 999 можуть задовольняти типу number.

## Варіант 12

SKU: рівно 8 символів, три великі латинські літери, дефіс, чотири ASCII-цифри. Приклади: ABC-1234, AAA-0000, ZZZ-9999. Відхиляються abc-1234, кирилиця, пробіли, інша довжина, число/null та перенос рядка в кінці. У JavaScript $ може збігатися перед кінцевим переносом; тому перевіряємо також length === 8. Не обрізаємо пробіли й не змінюємо регістр: контракт вимагає точного формату. Порушення — 400 INVALID_SKU до запису у сховище.

## Ідемпотентність DELETE

Повторення залишає той самий кінцевий стан: ресурсу немає. Коди можуть відрізнятися: перший DELETE — 204, наступний — 404. Це не порушує ідемпотентності. Для 204 перевіряємо response.text === '', не намагаємося читати відсутній JSON.

## Експеримент ownerId

Тимчасова заміна .json(toPublic(order)) на .json(order) у POST додає внутрішнє ownerId. У нашому наборі впали 8 перевірок: 6 зі схемою і 2 порівняння POST із наступним GET/списком. Решта 55 пройшли. Це відрізняється від очікування методички «лише схема»: повне порівняння об’єктів теж бачить зайве поле. Після відновлення коду всі 63 тести проходять.

## Postman та Newman

Колекція містить 8 запитів і 17 assertions. Login зберігає token; Create зберігає orderId; наступні запити використовують змінні. Є правильний і неправильний SKU та перевірка, що неправильне замовлення не збережено. Newman запускає той самий JSON і створює CLI, JUnit та JSON результати. Не запускай колекцію повторно на заповненому сервері без перезапуску: сценарій зі списком очікує порожній початковий стан.

## Як читати реалізацію

- src/app.ts — фабрика, маршрути, валідація й сховища.
- src/server.ts — локальний ручний запуск.
- tests/orders.test.ts — CRUD, заголовки, суми й побічні ефекти.
- tests/sku.test.ts — параметризація варіанта 12.
- tests/access.test.ts — вхід, чужі ресурси й ізоляція.
- tests/schemas/order.schema.ts та tests/schema.ts — контракти й Ajv.
- postman/orders.postman_collection.json — переносима колекція без збережених робочих токенів.

## Обмеження навчального API

Дані в пам’яті, токени без строку дії, два навчальні користувачі; це не production-система. Сервер прив’язаний до 127.0.0.1. У coverage враховується src/app.ts, а оболонка src/server.ts перевіряється реальним запуском Newman. Newman 6 має застарілі транзитивні залежності за npm audit; за вимогою методички використовується лише для цієї локальної навчальної колекції. Автоматичне force-пониження версії не застосовано.
